# RAG 운영은 후순위 — 현재 프로젝트에서 우선순위가 낮음

사용자가 "RAG는 현재 프로젝트에서는 우선순위가 낮다"고 밝혔다.
커리큘럼 순회의 맨 뒤로 보내고, 레슨 0001 자기진단에서도 성숙도 총점과
"다음에 다룰 것" 순위 계산에서 제외했다(`data-defer`). 완전 제외는 아니다.

## Implications

- 다음 레슨은 **오류분석 → 평가셋 → LLM-as-judge** 축으로 직진한다.
  검색 품질 분리 측정(retrieval recall 등)은 다루지 않는다.
- 레슨의 예시·실습 소재로 RAG를 쓰지 않는다. 사용자의 실제 워크로드로 예시를 든다.
- **미확인 사항**: 그렇다면 프로덕션에서 돌리는 LLM 기능이 정확히 무엇인가?
  (요약 / 분류 / 생성 / 대화 / 에이전트?) 실패 유형과 평가 설계가 여기에 전면 의존하므로
  다음 세션에서 반드시 확인한다. 레슨 0001 실습 산출물(실패 유형 목록)에서 자연히 드러날 수도 있다.
