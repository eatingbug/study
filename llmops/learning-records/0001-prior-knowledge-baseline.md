# 시작 기준선: 프로덕션 LLM 운영 경험 있음, 운영 체계 어휘는 없음

사용자는 프로덕션에서 LLM 기능을 이미 운영 중이며 사내 LLM 로그·트래픽에 접근할 수 있다.
따라서 API 사용법·프롬프트 작성법·"LLM이란 무엇인가" 류는 가르치지 않는다.
반면 운영 체계(평가·관측성·비용·배포)를 **언어화된 개념**으로 갖고 있지 않다고 본인이 밝혔고,
"전체 영역을 한 번씩 개념 정립"을 요청했다 → 깊이보다 **폭 우선**으로 진행한다.

## Evidence

- 인터뷰 응답: 현재 수준 = "프로덕션에서 LLM 기능을 운영 중",
  우선 영역 = 특정 영역을 고르지 않고 "전체적으로 개념을 한번씩 적립하는 것이 필요함".
- 실습 환경: OpenAI API 키 O / Anthropic 키 X / 사내 로그 접근 O.

## Implications

- 레슨은 "설명"보다 **본인 시스템에 대한 진단**을 시켜야 한다. 추상적 설명은 이미 아는 것과 겹쳐 지루하다.
- 실습 코드는 `openai` SDK 기준. Anthropic 전제 코드는 실행 불가 → 죽은 레슨이 된다.
- 사내 실제 로그가 있다는 것이 최대 자산이다. 합성 예제 대신 **본인 트레이스**로 실습을 설계한다.
  단 블로그 공개 시에는 익명화/합성 재현이 필수(→ [MISSION.md](../MISSION.md) 제약).
- 다음 세션의 ZPD는 레슨 0001의 자기진단 결과로 확정한다. 미확정 상태로 0002를 만들지 않는다.
