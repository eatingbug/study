# Mission: LLMOps

## Why

프로덕션에서 운영 중인 LLM 기능은 **루브릭 기반 영어 작문 자동채점**이다 (학습자는 한국인).
이미 돌리고 있지만, 운영 체계(평가·관측성·비용·배포)를 언어화된 개념으로 갖고 있지 않다.
LLMOps 전 영역의 개념을 한 번씩 정립하고, 각 영역을 실제 사내 로그/트래픽으로 실습해 검증한 뒤,
개인 기술 블로그(velog/Medium)에 시리즈로 공개해 "LLM을 운영해 본 사람"이라는 커리어 자산을 만든다.

## Success looks like

- LLMOps 핵심 영역(개념 지도 / 오류분석 / Eval / LLM-as-judge / 관측성 / 비용·토큰 / 프롬프트 CI·배포 / 서빙)을
  각각 "정의 + 우리 서비스에서의 현재 상태 + 개선 조치" 세 줄로 즉석에서 설명할 수 있다.
  (RAG 운영은 아래 참고 — 현재 프로젝트 우선순위가 낮아 뒤로 미룬다.)
- 사내 실제 로그에서 뽑은 평가 데이터셋으로, 프롬프트 변경을 자동 판정하는 회귀 테스트를 최소 1개 돌린다.
- 각 영역마다 재현 가능한 실습 결과(숫자 또는 스크린샷)를 1개 이상 확보한다 — 이것이 글의 근거가 된다.
- 블로그 글을 최소 3편 발행한다. 각 글은 남의 요약이 아니라 본인 실험 결과를 담는다.

## Constraints

- 실습 환경: OpenAI API 키 보유, 사내 LLM 로그/트래픽 접근 가능. Anthropic 키 없음 → 실습 코드는 OpenAI SDK 기준.
- **사람 채점자 점수(ground truth)가 없다.** LLM 채점 결과만 존재한다.
  → 정답 대비 지표(일치율·QWK·공정성 검증)는 라벨을 확보한 뒤에야 계산 가능하다.
  → 아래 "회귀 테스트 1개" 성공 기준도 라벨 확보가 선행 조건이다.
  → 그 전까지는 라벨 없이 되는 것(일관성·분포·길이 상관)으로 진단한다.
- 커리큘럼은 **중립적 영역 순회**를 유지한다 (사용자 결정). 채점 도메인은 예시·실습 소재로만 쓴다.
- 사내 로그는 외부 공개 불가 → 블로그용으로는 반드시 익명화/합성 데이터로 재현할 것.
- 한국어로 학습하고 한국어로 쓴다.
- 레슨은 짧게. 한 세션에 하나의 손에 잡히는 성과.

## Out of scope

- **RAG 파이프라인 운영 — 후순위 (2026-08-04 하향)**
  현재 프로젝트에서 우선순위가 낮다. 완전 제외는 아니고 순회의 맨 뒤로 보낸다.
  다른 영역을 한 바퀴 돈 뒤, 또는 프로젝트에서 검색 품질이 문제가 되는 시점에 되살린다.
  → 레슨 0001 자기진단 위젯에서 `data-defer` 로 점수·순위 계산에서 제외됨.
- 모델 파인튜닝 / 사전학습 (LLMOps가 아니라 ML 학습 영역)
- GPU 클러스터 구축·쿠버네티스 인프라 운영 (서빙은 "개념 + 지표 읽기" 수준까지만)
- 에이전트 프레임워크 비교 리뷰 (도구 카탈로그가 아니라 운영 원리에 집중)
