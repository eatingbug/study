### 실제 워크로드: 루브릭 기반 영어 작문 자동채점 (확인됨)

→ 상세는 [learning-records/0003-product-is-a-judge.md](./learning-records/0003-product-is-a-judge.md)

**모든 레슨의 예시는 이 도메인으로 든다.** 답안·루브릭·밴드·채점자 일치도.
일반적인 챗봇/요약 예시로 설명하면 사용자가 자기 시스템으로 번역하는 비용을 대신 물게 된다.

**절대 헷갈리지 말 것 — 두 개의 judge:**
- Judge A = 제품(루브릭 채점기). 출력은 **서열형 밴드 점수**. 정답은 사람 채점자 점수.
- Judge B = A를 평가하는 것. 출력은 **실패 유형별 이진 판정**.
- "판정은 이진으로"는 **B에만** 적용된다. A에 적용하면 도메인과 충돌한다.

**교육 순서**: 밴드별 혼동행렬 → 그 다음 QWK(요약 통계, 한계 명시). QWK 먼저 가르치지 말 것.

**쓰지 말아야 할 처방**: verbosity/position 편향 완화책(swap augmentation 등)은
쌍대비교 judge용이다. 단일 응답 루브릭 채점에는 부적합.

### 사용자 결정 (2026-08-04) — 존중할 것

1. **커리큘럼을 채점기 중심으로 재설정하는 안을 제안했고, 사용자가 거절했다.**
   선택: "원래 계획 유지 — 중립적 8영역 순회".
   → MISSION.md 의 성공 기준을 채점기 중심으로 다시 쓰지 않는다.
   → 각 레슨은 **일반 LLMOps 개념**을 가르치고, 채점 도메인은 **예시·실습 소재로만** 쓴다.
   → 다시 제안하지 말 것. 사용자가 원하면 직접 말할 것이다.

2. **사람 채점자 점수(ground truth)가 없다.** LLM 채점 결과만 존재한다.
   → 어떤 일치도 지표(QWK 등)도 지금은 계산 불가. 라벨이 선행 조건이다.
   → 그래서 "라벨 0개로도 가능한 진단"을 우선 설계한다: 점수 분포 히스토그램,
     길이–점수 상관, 재채점 자기 일관성. 세 가지 다 사람 점수 없이 돌아간다.
   → L1 편향 가설 검증은 라벨 확보 후로 미룬다. 순서: 진단 → 라벨 스키마 → 보정셋 → 일치도 → 편향.
- 사내 데이터는 실습에만, 블로그에는 합성 데이터로 재현 — 매 레슨에서 리마인드.
