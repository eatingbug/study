# 매일 배워 쓰고, 매주 한 편 발행하기

## 목표와 기본값

레슨을 읽고, 기억에서 꺼내 자기 말로 쓰고, 작은 상황에 적용한다.
그 결과를 모아 매주 블로그 한 편으로 발전시킨다.
기준 시간대는 Asia/Seoul, 한 주는 월요일~일요일(ISO 주차)이다.
하루 기본 시간은 30분이다. 독자는 해당 개념을 처음 배우는 동료 개발자다.
발행 대상은 [eatingbug.github.io](https://eatingbug.github.io), 발행 시각은 일요일 21:00이다.
월~목 문단을 쌓고, 금요일에는 직접 얼개·초고를 쓰고, 주말에는 교정·발행한다.
금요일과 주말에도 레슨 학습과 새 문단을 남긴다. 짧은 복습과 작은 글로 범위를 조절한다.

매일 최소 레슨 한 개를 학습하고 자기 문단 한 개를 남긴다.
한 주 목표는 저장소 전체에서 블로그 한 편이다. 주제마다 한 편씩 요구하지 않는다.
미결 레슨이 있으면 그 레슨을 복습하고 이어 쓴다.
`새 레슨을 만들었다`, `읽었다`, `직접 썼다`, `적용했다`, `발행했다`를 구별한다.
빠진 날은 그대로 두고 오늘부터 재개한다. 과거 날짜의 실적을 만들어 채우지 않는다.

## 매일 — 읽기 → 회상 → 쓰기 → 적용 → 피드백

1. 주제를 정하고 `MISSION.md`, `NOTES.md`, 최근 `learning-records/`, `summaries/`를 읽는다.
   가장 앞 미결 레슨을 선택한다. 만료이면 AGENTS.md의 재독 절차를 먼저 따른다.
   새 레슨을 열 수 있으면 `teach`로 하나의 작은 성과에 맞춰 저작한다.
   레슨을 실제로 열 때만 빈 요약을 만들고 시계를 시작한다.
2. 레슨 한 개와 필요한 1차 자료 대목을 읽는다.
   자료를 잠시 덮고 핵심을 설명한 뒤 다시 대조한다.
3. 블로그 저장소의 해당 주간 GitHub 이슈에 사용자가 직접 최소 한 문단을 댓글로 쓴다.
   핵심 주장과 그렇게 생각한 이유를 연결한다. 목록이나 복사한 인용만으로 대체하지 않는다.
   `python3 tools/writing.py daily`로 오늘 기록을 만들고 해당 댓글의 고유 URL을 남긴다.
   이미 쓴 글의 링크를 다시 붙이는 것으로 오늘 쓰기를 대신하지 않는다.
   일일 원문은 이슈 댓글 한 곳에 둔다. 이슈가 없으면 사용자가 만들거나 생성을 명시적으로 지시한다.
   에이전트는 별도 지시 없이 이슈·댓글을 작성하거나 전송하지 않는다.
4. 작은 적용 하나를 시도하고 행동·결과·한계를 기록한다.
   레슨 실습으로 충족할 수 있다. 업무 적용이 어려우면 합성 예시·계산·설계 판단으로 축소한다.
   실행하지 못했다면 `미실행`과 다음 행동을 적는다. 계획을 실행 결과로 기록하지 않는다.
5. 에이전트는 빠진 주장·오류·출처·관찰과 추론의 구분을 피드백한다.
   사용자가 고친 원문도 보존한다. 요약 채점에는 사용자가 쓴 문장만 사용한다.
   이슈 댓글의 글을 요약으로 제출하면 해당 문장을 그대로 옮기고 원문 댓글 링크를 남긴다.
   레슨을 닫을 수 있는지는 AGENTS.md의 요약·필수 실행 계약으로 판정한다.
6. 다음날 확인할 회상 질문 하나를 남긴다.
   다음 학습 세션에서 먼저 답하고, 틀리거나 막힌 부분을 오늘 학습에 반영한다.

쓰기 목표와 레슨 닫힘은 별개다. 한 문단을 썼어도 claim을 빠뜨렸다면 레슨은 미결이다.
스윕 레슨도 오늘의 작은 적용은 시도하되, 과거 필수 실습을 소급 완료할 의무는 없다.
에이전트는 질문·구조 피드백·기계적 교정을 돕는다.
일일 문단과 주간 본문의 초고·윤문·예시문은 사용자가 직접 쓴다.
기계적 교정은 맞춤법·주술 호응·긴 문장의 분할에 한정하고 주장이나 예시를 추가하지 않는다.
못 쓴 날의 한 줄 메모는 복귀 발판으로 남길 수 있지만, 최소 한 문단 목표를 달성했다고 세지 않는다.

## 매주 — 하나의 질문으로 묶기 → 직접 쓰기 → 교정 → 발행 → 환류

1. `python3 tools/writing.py weekly`로 이번 주 초안 틀을 만든다.
   해당 주간 이슈의 댓글·일일 기록·통과 요약을 훑고 독자에게 답할 질문 하나를 고른다.
   일주일치 레슨을 전부 담기보다 한 가지 설명과 적용 결과를 중심으로 고른다.
2. 선택한 원문 댓글·레슨·1차 자료 링크를 주간 파일에 남긴다.
   사용자가 직접 쓴 얼개와 초고를 `writing/weekly/`에 둔다.
   에이전트는 질문과 구조 지적, 기계적 교정만 돕고 원문과 요약 판정을 보존한다.
   관찰하지 않은 경험·숫자·성과를 추가하지 않는다.
3. 독자의 문제 → 배운 원리 → 시도와 결과 → 한계와 다음 질문 순으로 다듬는다.
   미실행이면 학습·해설 글로 범위를 정하고 경험담처럼 쓰지 않는다.
   확인이 덜 된 주장은 초안에 표시하고, 발행 전에 검증하거나 범위를 줄인다.
4. 본문과 출처를 확인하면 `상태: 검토완료`로 바꾼다.
   `python3 tools/writing.py post --slug <영문-주제>`로 Jekyll 포스트의 빈 틀을 만든다.
   사용자가 검토한 본문만 옮기고 제목·주제별 카테고리를 채운다.
   파일을 블로그 저장소의 `_posts/`로 옮기는 준비까지 돕고 실제 발행은 사용자가 한다.
   실제 사이트에서 글이 열리는 것을 확인하고 URL·날짜를 기록했을 때만 `상태: 발행`으로 바꾼다.
5. 다음 주에 받은 질문·반례·정정을 같은 주간 파일에 적는다.
   다음 레슨 선택을 바꿀 발견만 해당 주제의 `learning-records/`로 승격한다.

주말에는 일일 기록이 가리키는 그날의 실제 댓글 문단, 학습 레슨 링크, 적용 기록을 세어 본다.
주간 글은 초안·검토완료·발행을 따로 센다. 파일이 있다는 이유로 학습·쓰기를 완료 처리하지 않는다.

## 저장 위치와 공개 범위

| 자료 | 위치 | 역할 |
|---|---|---|
| 레슨별 요약·필수 실행 | `<topic>/summaries/000N-*.md` | 레슨 닫힘 판정 원본 |
| 날짜별 원문 링크·적용·질문 | `writing/daily/YYYY-MM-DD.md` | 주간 이슈 댓글로 이어지는 일일 기록 |
| 일일 문단 원문 | 블로그의 주간 GitHub 이슈 댓글 | 사용자가 직접 쓴 글의 원본 |
| 사용자 초안·출처·발행 URL | `writing/weekly/YYYY-Www.md` | 주간 한 편의 교정·발행 기록 |
| Jekyll 포스트 준비본 | `writing/posts/YYYY-MM-DD-slug.md` | 검토한 본문을 담아 `_posts/`로 전달 |
| 다음 학습을 바꾸는 발견 | `<topic>/learning-records/000N-*.md` | 후속 레슨 설계 근거 |

`writing/`은 Pages 배포 allow-list 밖이다. PR 머지도 블로그 발행으로 세지 않는다.
다만 Git 저장소에 커밋한 내용은 저장소의 공개 범위를 따른다.
사내 원자료·식별 정보는 넣지 않고, 허용된 집계 수치나 명시한 합성 예시만 남긴다.

빈 틀은 `templates/`에서 관리한다. 파일 생성 명령은 기존 파일을 덮어쓰지 않는다.
일일·주간 틀 생성만으로 레슨을 열거나 요약의 48시간 시계를 시작하지 않는다.

## 블로그 전달 규약

포스트는 Jekyll + Chirpy 형식이다. 파일명은 발행일과 영문 slug로 짓고,
frontmatter에 `title`, `date`(+0900), 주제별 `categories`, `tags`를 둔다.
`tags`에는 `주간글`을 포함하고 제목에 주차·회차를 붙이지 않는다.
레슨 링크는 study의 공개 HTML URL, 원문은 GitHub 댓글 URL을 사용한다.
주간 작업 파일의 내부 메모와 체크리스트는 공개 포스트 본문에 옮기지 않는다.

블로그는 main/master push 또는 수동 실행으로 빌드한다. 날짜만 미래로 지정하면 자동 발행되지 않는다.
일요일 21:00 이후 사용자가 push하거나 배포 워크플로를 수동 실행하고 사이트를 확인한다.
이번 설정 변경은 study에 한정하며 블로그 저장소의 규약·배포 설정은 변경하지 않는다.
알림이나 예약 자동화도 이번 범위에 포함하지 않는다.
