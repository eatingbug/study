# 0001 — 레슨은 산출물이 나와야 닫힌다

날짜: 2026-09-19 · 상태: 채택

## 맥락

이 저장소는 `teach` 스킬 규약으로 운영된다. 스킬은 무엇을 가르칠지는 정하지만
**배운 것을 실행했는지는 추적하지 않는다.** 그 빈칸에서 관측된 것:

- 레슨 6개(valley 4 · llmops 2)가 쌓이는 동안 산출물은 0개다.
  valley 숙제 리포트 미제출, llmops 블로그 목표 3편 대비 0편.
- 마지막 커밋 2026-08-23 이후 4주 공백.
- `valley/NOTES.md` 에 "할인율 r을 잊었다 (2026-08-07)" 가 기록돼 있다.
  L0001 을 완료한 뒤였다. 읽은 것이 남지 않는다는 증거가 이미 문서 안에 있었다.

Dan Martell 의 SELF 프레임워크 용어로는 select(미션·자료)와 extract(레슨·용어집)는
이 저장소가 이미 갖고 있고, **live it(48시간 안의 실행)** 이 통째로 비어 있었다.
비어 있는 나머지 — feed(매일 드립) · forge(반복 숙달) — 는 이번 범위에서 제외했다.
한 번에 하나만 고친다.

## 결정

레슨의 완료를 **읽음**이 아니라 **산출물**로 정의한다. 규칙 전문은
[/CLAUDE.md](../../CLAUDE.md) 에 있고, 여기에는 왜 그렇게 정했는지만 남긴다.

1. **상태는 세 개다 — 열림 / 만료 / 닫힘.** 48시간이 지나면 만료되고,
   만료는 레슨 재독으로만 복구된다.
   상태는 **요약 파일 하나에서 전부 읽어 낸다** — 없음 / `작성중`+날짜 / `통과`.
   그래서 레슨을 여는 세션이 즉시 `작성중` 파일을 만들어야 한다.
   (초안에서 이걸 빠뜨렸더니 열림과 만료가 파일상 구별되지 않아 3상태가 2상태로 무너졌다.
   별도 상태 파일을 두는 대신 요약 파일에 판정 줄을 붙이는 쪽을 택했다 — 어긋날 것이 하나뿐이다.)
2. **집행은 Claude 세션이 한다.** CI 검사를 만들지 않는다.
3. **계약은 레슨 HTML 이 스스로 선언한다** (`lesson-claim-*` · `lesson-action-*`).
4. **요약은 모든 레슨의 항상 필수 항목이고, 선언된 핵심 주장 대비 채점한다.**
5. **필수/선택은 저작 시 내가 분류하고 사용자가 뒤집을 수 있다.**
6. **기존 6개 레슨은 요약만 소급한다.** 사면 없음. 한 세션에 한 편씩 순차로 닫는다.
   스윕으로 닫힌 레슨의 필수 실습 항목은 영구히 미결로 남기고 닫힘 판정에서 뺀다 —
   일반 규칙은 스윕 이후 열리는 레슨부터 적용된다.

## 트레이드오프 — 무엇과 무엇을 바꿨는가

**차단 vs 진도.** 차단을 택했다. 부채를 보여 주기만 하는 쪽이 부드럽지만,
이 저장소의 실패는 "몰라서"가 아니라 "쌓아 두고 넘어가서" 생겼다.
보여 주기만 하는 설계는 이미 한 번 실패한 설계다 — `NOTES.md` 의 미결 항목이
표시돼 있었는데도 4주가 지났다.

**대가는 valley 가 치른다.** Week 12 마감이 있는데 0005(ERP) 앞에 요약 4편이 놓인다.
사용자가 이 비용을 숫자로 확인한 뒤 선택했다.

**세션 집행 vs CI 집행.** 세션을 택했다. 실제로 "다음 레슨을 시작"하는 행위자가
세션이라 차단 지점이 정확하고, CI 는 이미 써 버린 뒤에야 막는다. 대가는 규칙을
읽지 않는 다른 도구가 우회할 수 있다는 것 — 학습용 개인 저장소에서는 감수할 만하다.

**HTML 선언 vs 별도 추적 파일.** HTML 을 택했다. `build-index.py` 가 이미
목록을 손으로 관리하지 않고 문서의 `<meta>` 에서 뽑는 선례를 만들어 두었고,
상태를 별도 파일에 이중으로 적으면 어긋난다. 대가는 기존 레슨 6개에 소급 입력이
필요했다는 것 (이 커밋에서 처리).

**소급 vs 사면.** 소급을 택했다. 사면하면 4주 전에 읽고 잊은 토대 위에 0005 를 쌓는다.
그리고 소급 스윕 자체가 4주 공백 뒤의 복습 스윕을 겸한다.
**스윕은 만료 규칙의 예외가 아니다** — 요약을 쓰려면 레슨을 다시 열어야 하므로,
스윕이 곧 만료 복구가 요구하는 재독이다. 이 해석을 명시해 두지 않으면
다음 세션이 서로 어긋나는 두 규칙을 발견하게 된다.

## 버린 대안

- **`learning-records/` 에 요약과 실습 숫자를 전부 넣기.**
  `teach` 스킬의 `LEARNING-RECORD-FORMAT.md` 가 "세션별 활동 로그는 학습기록이 아니다"
  라고 명시한다. 매 레슨의 요약을 쌓으면 학습기록이 저널이 되고,
  ZPD 계산의 입력값이 잡음에 묻힌다. → `summaries/` 를 따로 냈다.
- **`<topic>/results/` 신설해 숫자를 분리.** 요약과 그때 나온 숫자가 갈라진다.
  블로그·리포트 초고로 재활용할 때 둘을 다시 합쳐야 한다. → 요약 파일 안에 함께 둔다.
- **CI 게이트.** 위 참조.
- **워크스페이스별로 다른 규칙.** valley 는 마감형, llmops 는 개방형이라 갈라 볼 만했다.
  같은 규칙을 두 벌 유지하는 비용이 이득보다 크다고 판단했다.

## 되돌리는 법

`CLAUDE.md` 의 해당 절을 지우면 규칙이 사라진다. 레슨의 `lesson-*` meta 는
남겨 두어도 무해하다 — 빌더가 읽지 않는다. `summaries/` 는 사용자가 쓴 글이므로
규칙을 되돌려도 지우지 않는다.
